# Stages and default goals

Each stage is usually one 6 week cycle, sometimes two. Offer the defaults below,
rewritten for the app's own loop (example loop: "add a plant, get a reminder, mark
it watered"). The user edits; nothing here is required.

Store rules change. Where a stage mentions a store requirement, check the current
official page before stating a number or a date.

## 1. Working loop on my phone

- **Goal:** "The whole loop works on my own phone, in a real build, by <date>."
- **The one number:** days in the last two weeks I used the app for real. Target: 10.
- **Must dos:** the loop works end to end with no dev server; data survives closing
  the app; a crash reporter is installed; one other person has tried it.
- **Not this cycle:** accounts, payments, settings screens, a second platform,
  visual polish.
- **Gate:** I use it without being asked, and one other person got through the
  loop without help.

## 2. Into the stores

- **Goal:** "Live in the App Store (and Google Play) by <date>."
- **The one number:** stores the app is live in. Target: the ones chosen.
- **Must dos:** final app name and bundle ID; developer accounts verified; store
  testing track started (start any tester clock first, it runs on the calendar);
  listing with screenshots and privacy answers; first submission sent.
- **Not this cycle:** new features. Fix only what review or testers find.
- **Gate:** a stranger can install it from the store.

## 3. First 100 weekly users

- **Goal:** "100 people use the loop every week by <date>."
- **The one number:** weekly active users who completed the loop. Target: 100.
- **Must dos:** analytics on the loop's key step; one place people can find the
  app each week (a post, a community, a friend list); talk to one real user a
  week; fix the top drop off point.
- **Not this cycle:** payments, big new features, a redesign.
- **Gate:** a steady number of new people each week who were not asked personally.

## 4. Keeping them

- **Goal:** "<percent> of new users are still using it a week later, by <date>."
- **The one number:** week one retention. Target: set from the current value.
- **Must dos:** see who stays and who leaves; message both; improve the first run
  for a new user; one reason to come back (a reminder, a streak, saved progress).
- **Not this cycle:** paid ads, new platforms.
- **Gate:** retention holds steady for three weekly groups of new users.

## 5. First paying users

- **Goal:** "First <number> paying users by <date>."
- **The one number:** paying users. Target: a small first number, like 10.
- **Must dos:** decide what sits behind the paywall; purchases tested on a real
  device in a release build; a restore purchases path; ask early users what they
  would pay for.
- **Not this cycle:** price experiments with too few users to read them.
- **Gate:** people pay without being asked personally.

After stage 5, keep cycling on whichever number matters most: growth, retention or
revenue. Ask the user which.
